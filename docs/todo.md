
## L10n：`L10n.key` 不该是个 String（量过了，58 个文件）

**判据**：把 `L10n.key` 的返回类型换成 `L10n.Key`（一个包着 String 的结构体），
让"没查过表的 key"和"已经查过的字"在类型上分开。
现在两者都是 `String`，**把 key 直接摆上屏是合法代码** ——
编译器不响、界面看着正常，只有非英文用户看得见。

**为什么要做**：2026-09-01 一个下午撞见**四种形状**：
1. `Text(L10n.key("…"))` —— 60 处，整条付费路径（已修）
2. key 存进变量，`Text(n)` 逐字画 —— 网关 29 条失败文案（已修）
3. 交给自定义辅助函数 `footerButton(label:)`（已修）
4. 压根没登记的裸字面量 `"Signed out"`（已修）

守卫现在列的是"接手方本身逐字"的十个 sink。**列名字这条路永远差下一个**
—— 四种形状里有三种是列表没覆盖到的时候撞见的。

**代价（实测，不是估的）**：改类型后 `swift build` 报 **2670 处错、58 个文件**。
每一处要判"这个 key 是存进 `.palmier` 工程文件、还是当场上屏" ——
判错就是把语言写死进用户的工程。**这是一整块活，不是顺手能带的。**

**已排除**：不能靠 `check-l10n.py` 补 —— 它量的是词条表全不全，
不是屏幕用不用；那 60 处出事的时候它全程报绿。
